# Отчёт по учебной практике

## Введение

Учебная практика проходила с 28 сентября по 9 октября 2026 года. Тема практики: «Осуществление интеграции программных модулей». Индивидуальное задание: разработка учебной операционной системы StudyOS с базовыми сервисами (управление пользователями, файлами, процессами, памятью) и журналированием системных вызовов.

**Цель практики** — получить навыки проектирования, разработки, интеграции и тестирования программных модулей на примере учебной операционной системы.

## 1. Предметная область

Учебная операционная система StudyOS имитирует работу реальной ОС. Система управляет пользователями, процессами, памятью и файловой системой. Роль физического диска выполняет база данных SQLite. Файловая система — плоская (пути вида `/file.txt`), с разграничением прав доступа по ролям.

## 2. Архитектура системы

Система состоит из девяти модулей:

- `db.py` — работа с SQLite;
- `kernel.py` — состояние ядра (память, PID);
- `auth.py` — аутентификация и права;
- `fs.py` — файловая система;
- `scheduler.py` — планировщик процессов;
- `syscalls.py` — системные вызовы;
- `shell.py` — командная оболочка;
- `logger.py` — логирование;
- `config.py` — конфигурация.

Модули связаны однонаправленно: `shell` вызывает `syscalls`, `syscalls` вызывает `kernel` и подсистемы, подсистемы обращаются к `db`.

## 3. Реализованные функции

- **Управление пользователями:** регистрация, вход, роли (`admin`, `user`, `guest`), разграничение прав.
- **Файловая система:** создание, чтение, запись, удаление, просмотр списка файлов.
- **Управление процессами:** `run`, `ps`, `kill`.
- **Управление памятью:** выделение, освобождение, контроль лимита (1024 МБ).
- **Журналирование:** все системные вызовы записываются в `syscalls_log`.

## 4. Структура базы данных

Таблицы: `users`, `files`, `processes`, `syscalls_log`, `memory_state`, `roles`.

- `users`: `id`, `login`, `password_hash`, `role`, `created_at`.
- `files`: `id`, `path`, `content`, `owner`, `created_at`.
- `processes`: `pid`, `name`, `state`, `owner`, `memory_used`, `created_at`.
- `syscalls_log`: `id`, `syscall_name`, `args`, `user`, `status`, `timestamp`.
- `memory_state`: `id`, `used`, `limit_val`.
- `roles`: `id`, `name`, `description`.

## 5. Тестирование

Проведено:
- модульное тестирование (`test_kernel.py`, `test_os.py`);
- функциональное тестирование (`test_fs.py`, `test_fs_functional.py`, `test_scheduler.py`, `test_scheduler_functional.py`, `test_syscalls_functional.py`);
- интеграционное тестирование (`test_integration.py`, `test_integration_full.py`);
- системное тестирование (SS-01 — SS-04);
- стресс-тестирование (`test_stress.py`).

**Итог:** 11 тестовых модулей, 60+ тестовых функций — все проходят (`пройдено 11, провалено 0`). Найдено 4 дефекта: 3 закрыто, 1 отложен с обоснованием.

## 6. Результаты

Система запускается командой `python -m src.shell` (или `uv run python -m src.shell`). Все заявленные команды работают, права доступа разграничены, журнал заполняется, тесты проходят.
